# Document discovery and patient association

File-share and object-storage scans use the same bounded extraction and detection pipeline. Native text and English printed OCR produce PII findings whether or not a patient relationship can be established. A clinical term alone is reported as clinical content.

For PDFs and supported raster files, the isolated parser also returns transient word positions within each original rendered page or image frame. The application validates token agreement, dimensions, original-unit inventory and limits before using those positions. Coordinates and processing text are held in memory; they are not saved in findings or metadata. Evidence capture remains a separate, explicit option for encrypted bounded matching values and excerpts.

The `explicit_patient_fields_geometry_v1` policy identifies candidate records beginning with explicit patient fields. It supports compact forms, vertically stacked forms and two columns with a supported empty gutter. Record identity never crosses an original page/frame, a native/OCR channel, a removed duplicate-line barrier or an inferred record boundary. Only a unique detected patient reference can establish patient-linked clinical content. The record identifier is not stored as part of the classification.

Unlabelled text, unknown patient headers, conflicting identifiers, role-qualified identifiers, uncertain columns, overlapping words and headered tables remain unlinked. An unreadable new patient header terminates the previous candidate. The policy is a conservative heuristic, not proof of identity or measured hospital accuracy; it can miss associations and must be evaluated on the hospital corpus. It does not understand the meaning of a diagnosis or determine whether a clinical statement is true of a patient.

Each canonical word is assigned exactly once. If text alignment, geometry or conservation fails, the available text is still detected with patient linkage disabled. Tika content that cannot be mapped to original coordinates is examined separately and stays unlinked. DOCX and other Office/Tika-only extraction remain partial and do not use this layout policy.

PDF reconciliation compares whole connected groups of overlapping native/OCR lines on the same original page. Every word in a group must have exactly one counterpart in the other channel, with equal NFC-normalized text and verified spatial agreement. This can resolve differing column grouping, such as two native column lines represented by one OCR line, without changing native word or block boundaries. Repeated words at distinct positions remain separate observations; there is no global value deduplication. Only whole OCR lines from a fully matched group are removed. Missing or conflicting words, competing overlaps and uncertain geometry retain the observations and disable patient linkage for the affected page channels; counts can therefore still include duplicates.

For accounted PDFs, the Tika fallback requests `sortByPosition` while disabling Tika's overlapping-text deduplication. A fallback page is omitted only when its ordered NFC-normalized text, including repetitions, equals the helper's native text for that same original page. The comparison normalizes whitespace but does not reorder or compare sets of words. Unmatched pages, text outside mapped pages and returned embedded content remain available for detection as unlinked supplements. Sorting Tika text does not make its coordinates or patient boundaries verified. Hospital evaluation must include native, mixed and image-only documents, including uncertain column layouts.

Coverage and association are separate. Completing a raster's processing does not establish OCR accuracy. A supported candidate record does not make a native-bearing PDF fully scanned; uninspected or incompletely represented content keeps its existing partial status. Metadata reports candidate counts, unverified-region counts, word-mapping completeness and a false hospital-accuracy-validation flag. These are processing counts, not patient counts.

Version-3 evaluation accepts independently reviewed original-page/frame rectangles using `document_rectangles_v1`. Gold binds to original file bytes, rendered dimensions and unit ordinals, not algorithm-produced region IDs. Include all records and background/negative regions. A predicted record spanning different gold rectangles cannot earn a correct association; wrong and unmapped predictions remain errors, and missed positive records remain false negatives. Partial coverage cannot become an acceptance pass. See [the evaluation contract](evaluation.md) for the manifest and sample requirements.
