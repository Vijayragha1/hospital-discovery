# Connector and format coverage

Current bundle: `20260922035303`. See [current validation](implementation-validation.md).

Historical bundle `20260922034011` has a [validation record](implementation-validation.md). Current behavior and remaining [document-layout limits](document-discovery.md) are described below.

This matrix describes implemented paths, not hospital-validated accuracy. Scanner statuses are part of each report and must accompany any findings export.

Historical release `20260922022904` has [release evidence](../fixtures/evaluation/boundary-release-validation.json) recording 488 passing regression tests and 44 subtests, 26 original-file boundary checks, 17 packaged PDF checks, 32 HTTPS checks and 10 comparison checks, with offline/source/runtime verification. Platform-specific parser, UI and live-connector checks are historical. Neither synthetic checks nor complete processing establish hospital corpus compatibility, Office completeness or recognition accuracy.

Defaults are 20 MiB per file/object, 10,000 objects per scan, 1,000,000 text characters per object, batches of at most 100 database rows, and 1,000 sampled rows/table. Wide MySQL/SQL Server tables may reduce batch/cell limits further and record truncation. Views and binary/unsupported column types remain explicit coverage gaps. Configured limits and failures are reported. These are conservative starting settings, not a hospital capacity recommendation.

The isolated OCR job additionally caps original units at 100, each rendered unit at 20 million pixels and the job at 55 seconds inside the gateway's outer deadline. It records omitted/failed units and text truncation. A processed blank page/frame is not a claim that it was legible or that OCR missed nothing. PDFBox feature inspection is separately bounded; a clean feature manifest alone never makes the PDF fully scanned. Image metadata values are not silently discarded as if inspected: their presence keeps coverage partial, including uninspected metadata inside encoded PDF image streams.

PDF geometry reconciliation initially requires an unrotated page with identical zero-origin MediaBox/CropBox, default UserUnit and consistent native/render dimensions. Other page geometries retain their observations but cannot pass that reconciliation gate. Native and OCR channels remain separate; only whole OCR lines in completely matched groups are omitted, and those barriers cannot join previously separated fragments. Missing words, conflicting text or competing word positions prevent that group's suppression and leave the page channels unlinked. For accounted PDFs, Tika requests `sortByPosition` and disables overlapping-text deduplication. Tika native content is omitted only when its ordered NFC-normalized text, after whitespace normalization and including repetitions, equals the helper's native text for the same original page. Unmatched/unmapped pages, text outside mapped pages and returned embedded content remain unlinked supplemental observations with duplicate uncertainty. These rules do not prove patient identity or full native-text representation.

The automatic document-layout policy validates token agreement, dimensions, complete original-unit inventory and word conservation before considering patient candidates. It supports compact forms, stacked records and supported two-column gutters, with an explicit unique patient field required for a clinical link. Unlabelled/ambiguous regions, overlapping words, conflicting identifiers, unsupported tables and unmapped supplements stay unlinked. Failed alignment or truncation retains available text for detection without enabling association. Geometry and processing text are transient; only fixed policy codes and counts enter metadata. This heuristic needs hospital calibration and independent evaluation; see [document discovery](document-discovery.md).

Object-storage documents use the same extraction/OCR paths below. Cloud listing pagination is not a point-in-time snapshot; ETag changes, access loss, sample caps and listing limits remain visible. See [cloud connector requirements](cloud-connectors.md) for exact endpoint, credential, timeout and coverage limits. Synthetic SDK/emulator tests do not establish actual hospital/provider access.

API checks and worker scans share a lock for each configured relational database, keyed by connector/host/port/database rather than credentials or selected tables. Canonicalize endpoint names during inventory: different DNS/IP aliases or separate application catalogs are not coordinated. See [database-operation limits](database-connectors.md).

Match counts count recognizer observations; OCR and extracted text can overlap. Counts are not unique values, records, patients, or diagnoses. General-purpose English NER does not reliably establish patient-versus-clinician identity, and clinical rules are deliberately limited.

Version-2 evaluation measures exact value occurrences within each source object, not original page/record/span correspondence. Version 3 adds original-record clinical presence and exact patient-reference association for native JSON/text, typed-primary-key SQLite reference exports and independently annotated original PDF-page/raster-frame rectangles. Rectangle gold binds to source-file bytes, original ordinals and rendered dimensions; it must cover observed words, including negative/background regions. Algorithm-produced region IDs are not reference annotations. CSV/TSV, Office and unvalidated document geometry remain unsupported association mappings, and partial content cannot pass accuracy acceptance. Neither metric scores semantic diagnosis relationships. See the [evaluation contract](evaluation.md) and [pilot completion audit](pilot-status.md).

Optional evidence capture applies after extraction and detection, without expanding supported formats or improving coverage status. It retains at most three encrypted examples per finding: a value of up to 256 characters and an excerpt of up to 400 characters. OCR examples reflect the recognized text, including possible recognition errors. Segment-relative offsets do not guarantee original page positions or stable database row identifiers. A schema/context-only classification can legitimately have no captured match. Default scans and existing older scans contain no examples; a new capture-enabled scan is required. Ordinary exports exclude this evidence.
